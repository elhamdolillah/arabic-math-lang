# مصفوفة اختبارات وأدلة اتصال UORI

**الحالة:** `TEST_PLAN` — خطة تحقق؛ لا تُحوّل خانة الخطة إلى نجاح إلا بعد إرفاق سجل قابل لإعادة الإنتاج.

## قاعدة القياس

يقاس كل ادعاء على أربعة محاور مستقلة: هوية الواجهة، إمكان الوصول، صحة التبادل، وسلامة الأثر. ويجب أن يذكر الاختبار البيئة والمعمارية وإصدار المحول والصلاحيات والعتاد أو المحاكي. فنجاح الاختبار البرمجي لا يثبت نجاح العتاد الحقيقي، ونجاح جهاز واحد لا يثبت التعميم.

## المصفوفة

| المجال | الاختبار الأدنى | بيئة الاختبار | الدليل المطلوب | الحكم عند النجاح |
|---|---|---|---|---|
| الاكتشاف | رصد الواجهة وتسجيل خصائصها | Sandbox أو نظام هدف | سجل وصف خام وبصمة | `DETECTED` |
| UART/Serial | loopback بمعدل بت معلوم | محاكي ثم محول فعلي | المدخلات، الإطارات، CRC، رمز الخروج | `VERIFIED_SIMULATION` أو `VERIFIED_TARGET` |
| DB9/DB25 | مطابقة الأطراف والاتجاه | لوحة اختبار معزولة | مخطط التوصيل وقياسات آمنة | قبول الهدف المحدد فقط |
| USB | تعداد جهاز اختبار وفئة معلومة | مضيف USB ومحاكي | وصف الجهاز، السجلات، حدود الطاقة | `VERIFIED_TARGET` عند اكتمالها |
| Bluetooth | اقتران طرف اختبار وتبادل رسالة | مكدس نظام أو متحكم | هوية الطرف، المفاتيح، السجل | لا يثبت وصولاً مباشراً |
| IR/مورس | إرسال واستقبال تسلسل معلوم | محاكي ثم باعث/حساس | شكل الإشارة، معدل الخطأ، سجل الزمن | قبول قناة محددة |
| Socket/MCP | تبادل مع طرف اختبار مصرح | loopback ثم شبكة معزولة | هوية الطرف، الرسائل، المهلة | نطاق الطرف المحدد |
| RJ45/LAN/Wi‑Fi | ping أو رسالة اختبار ضمن شبكة معزولة | شبكة اختبار | عناوين النطاق، الحزم، الجدار الناري | لا يثبت شبكة عالمية |
| Wi‑Fi Direct | اكتشاف واقتران وتبادل محدود | جهازان مملوكان للاختبار | موافقة الطرف وإلغاء القناة | قبول الاقتران المحدد |
| ضوئي/ليزر/ألياف | نقل تسلسل غير مؤثر | منصة بصرية آمنة | محاذاة، جودة الإشارة، إيقاف | يتطلب تحقق سلامة مستقل |
| بروتوكول مركب | اختبار نسخة ومكونات محددة | بيئة تكرارية | المواصفة، التبعيات، السجل | لا تعميم خارج الإصدار |
| الإلغاء | قطع القناة أثناء النقل | كل البيئات | زمن الإيقاف وحالة المخرج | شرط قبول إلزامي |
| العزل | محاولة وصول خارج النطاق | Sandbox | سجل الرفض وعدم الأثر | `PASS_ISOLATION` |
| الثبات | تكرار نفس المدخلات | بيئة ثابتة | مقارنة مخرجات وبصمات | شرط الحتمية حيث ينطبق |

## سلاسل الأدلة

ينشئ كل اختبار ملف نتائج خاماً، وملف وصف للبيئة، وبصمة للمدخلات والمخرجات، ونسخة السياسة، ونسخة المحول، ورمز الخروج، وحالة الاختبار. تربط الملفات بترتيب زمني في سلسلة SHA-256. وتثبت السلسلة سلامة السجل بعد إنشائه، لكنها لا تثبت وحدها صحة الاستنتاج أو سلامة العتاد.

## معيار الحكم

تكون النتيجة `PASS` عندما ينجح الاختبار المحدد وتطابق الأدلة العقد. وتكون `BLOCKED` عند غياب العتاد أو الصلاحية أو أداة الاختبار. وتكون `ABSTAIN` عندما تكون البيانات غير كافية لتحديد النتيجة. وتكون `PLANNED` عندما لم ينفذ الاختبار بعد. ولا يسمح النظام بترقية `PLANNED` أو `BLOCKED` إلى نجاح دون سجل جديد.

## الاختبار الرسمي

لا تُعد مصفوفة الاتصال برهان Coq، ولا تجعل اختبارات Python أو Assembly النتيجة إثباتاً رسمياً كاملاً. يمكن ربط بعض عقود الرسائل أو حدود الحساب بمبرهنات رسمية، لكن يجب الإبلاغ عن نطاق كل برهان منفصلاً عن اختبار النقل والعتاد.

`PASS_TEST_MATRIX_SPECIFICATION_WITH_EVIDENCE_BOUNDARIES`.
