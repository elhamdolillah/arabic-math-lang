# UORI Deterministic LLM

[العودة إلى خريطة UORI](UORI_OVERVIEW_AR.md)

## الوظيفة المقصودة

طبقة UORI Deterministic LLM ليست بديلاً عن المترجم أو البرهان. وظيفتها المقصودة هي اقتراح فرضيات، أو تحويل شرح عربي إلى بنية قابلة للفحص، أو تفسير نتيجة موثقة. أما القرار التنفيذي فيمر عبر قواعد اللغة والعقود والاختبارات، ولا يعتمد على نص مولد وحده.

## القواعد الدستورية

1. يُستخدم الحتمي عندما يكون المجال مستوفياً وحد الخطأ مقبولاً.
2. يُستخدم الفتري عندما تكون الحدود مضمونة.
3. يُستخدم الاحتمالي عندما يكون التوزيع مبنياً على بيانات كافية ومعايراً.
4. يُستخدم الذكاء الاصطناعي التوليدي لاقتراح الفرضيات أو الشرح.
5. يُمتنع عن الإجابة عندما لا يوجد دليل كافٍ.

## العلاقة باللغة

تتعامل الطبقة مع لغة UORI بوصفها لغة هدف ذات نحو وأنواع وعقود. لا يجوز للـLLM أن يضيف syscall أو صلاحية أو أثراً جانبياً غير موجود في العقد، ولا أن يقدم مخرجاته على أنها برهان رسمي.

## الحالة

**الحالة: مخطط/بحثي ما لم يرفق دليل مستقل.** لا يكفي وجود ملفات تجريبية أو أسماء مثل `qwen_demo` لإثبات نموذج LLM حتمي مكتمل. يجب إضافة لاحقاً مواصفة للنموذج، ومجموعة بيانات أو بروتوكول اختبار، وآلية ضبط البذرة والمخرجات، وسجل قابل لإعادة الإنتاج.

## الأدلة المطلوبة للترقية

يلزم لإعلان نموذج أولي تشغيل اختبارات تكرار مستقلة، وتثبيت إصدار النموذج، وتسجيل المدخلات والمخرجات والبصمات، وإظهار مسار الامتناع. ويلزم لإعلان حتمية تشغيلية تحديد معنى الحتمية وحدودها وعدم مساواتها بمجرد ثبات نص الاختبار.
