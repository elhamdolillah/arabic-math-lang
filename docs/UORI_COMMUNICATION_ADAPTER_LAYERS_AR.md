# طبقات محولات الاتصال في UORI

**الحالة:** `DESIGN_SPECIFICATION` — مواصفة معمارية غير مدعية لتنفيذ البروتوكولات فعلياً.

## الفكرة المركزية

لا تتعامل نواة UORI مع Bluetooth أو USB أو UART أو sockets بوصفها أوامر سحرية قابلة للتنفيذ الفوري. بل تستخدم محولاً ذا عقد واضح يربط بين وصف القدرة، ونقطة الوصول التي تسمح بها المنصة، ومترجم الرسائل، وسياسة الأمان، وسجل الدليل. ويظل التنفيذ المباشر اختياراً مقيداً لا يُفترض وجوده.

## الطبقات

| الطبقة | الوظيفة | المخرج | شرط الانتقال |
|---|---|---|---|
| 1. الاكتشاف | رصد أجهزة أو منافذ أو خدمات ظاهرة | `CapabilityObservation` | مصدر ملاحظة موثق |
| 2. الوصف | تحديد النوع والإصدار والاتجاه والقيود | `InterfaceDescriptor` | وصف غير ملتبس أو `ABSTAIN` |
| 3. المواءمة | اختيار محول مناسب أو إنشاء طلب محول | `AdapterPlan` | توافق مثبت أو طلب مراجعة |
| 4. التفويض | تحديد العمليات المسموحة والمدة والهدف | `AuthorizationLease` | موافقة وسياسة نطاقية |
| 5. العزل | تشغيل المحول في حيز محدود الموارد والصلاحيات | `IsolatedAdapter` | منع الوصول غير المعلن |
| 6. الترجمة | تحويل الرسائل بين النموذج الرياضي العربي والبروتوكول | `FrameTranslator` | اختبارات ترميز واتجاه |
| 7. النقل | قراءة أو كتابة عبر نقطة الوصول المصرح بها | `TransportResult` | قناة متاحة وقابلة للإلغاء |
| 8. الإثبات | تسجيل المدخلات والمخرجات والرموز والبصمات | `EvidenceRecord` | سجل قابل لإعادة القراءة |

## العقد الموحد

يمثل كل محول بالسجل التالي: اسم الواجهة، البروتوكول، الإصدار، نوع الطرف، اتجاه البيانات، نقطة الوصول، مستوى الصلاحية، نطاق العمليات، مهلة الإيقاف، مخاطر الطاقة أو الخصوصية، اختبار الاتصال، بصمة المحول، وحالة الدليل. لا يجوز للمحول تعديل النطاق الممنوح لنفسه أو طلب امتياز أعلى تلقائياً.

## محولات نموذجية

يمكن أن يستخدم Bluetooth محولاً يمر عبر مكدس النظام عندما يكون ذلك هو المسار المصرح به، أو محولاً منخفض المستوى عند توفر متحكم وتفويض مناسب. ويمكن لـ UART وDB9 وDB25 استخدام محولات تسلسلية أو متوازية، لكن اسم الموصل وحده لا يثبت الإشارة أو الجهد أو مخطط الأطراف. أما USB فيحتاج تمييز المضيف من الجهاز ووصف الفئة وإدارة الطاقة. وتحتاج sockets وMCP إلى هوية طرف وسياسة رسائل، لا إلى مجرد فتح منفذ.

## التنفيذ بلغة الآلة

تستطيع UORI، من حيث التصميم، أن تملك backend يولد تعليمات قريبة من العتاد لمحول معروف. لكن توليد تعليمات آلة لا يثبت صلاحية تنفيذها على منصة بعينها. يجب أن يحدد backend المعمارية، ونموذج الذاكرة، ومناطق I/O، وتعليمات الحاجز، وقيود الامتياز، وآلية الإلغاء. وإذا كانت المنصة تمنع الوصول المباشر، يبقى المحول في طبقة نظام التشغيل أو المحاكاة وتُسجل النتيجة وفق ذلك.

## التوازي بين الأنوية

يتكون UORI العالمي، في التصور الموزع، من أنوية مستقلة تتبادل رسائل موقعة ومحدودة النطاق. لا يمنح وجود عدة أنوية أياً منها حق التحكم في عتاد أو طرف آخر دون تفويض. ويجب أن يكون لكل رسالة معرف فريد، ووقت صلاحية، ونطاق، وسبب، وبصمة للسياق، وحالة قبول أو رفض.

## الفشل الآمن

عند فشل الوصف، أو غياب التعريف، أو تعارض الصلاحيات، أو وجود رسالة غير قابلة للتحقق، يتوقف المحول ويعيد `ABSTAIN` أو `BLOCKED`. ولا يُعاد تفسير الفشل على أنه نجاح جزئي. ويجب أن تكون حالات الإيقاف قابلة للاختبار قبل أي إرسال مؤثر.

## حدود المواصفة

هذه الوثيقة تثبت تصميم طبقات المحول وعقوده فقط. ولا تثبت أن UORI يفهم كل البروتوكولات، أو يتجاوز كل أنظمة التشغيل، أو يتصل تلقائياً بأي عتاد أو مستودع إنترنت. إثبات كل قدرة يحتاج عتاداً محدداً، ومواصفة قابلة للتدقيق، ومحولاً منفذاً، واختبارات إعادة إنتاج، وسجل SHA-256.
