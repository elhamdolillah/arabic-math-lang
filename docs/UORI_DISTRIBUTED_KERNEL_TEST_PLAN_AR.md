# خطة اختبارات النواة الموزعة في UORI

**الحالة:** `PLANNED_TEST_SPECIFICATION` — خطة قابلة للتنفيذ، وليست نتيجة اختبار.

## النطاق

تختبر الخطة نواتين أو أكثر تعملان في بيئات معزولة، مع محاكاة أو عتاد فعلي موثق صراحةً. لا تُعد المحاكاة إثباتاً لخصائص العتاد الحقيقي، ولا يُسمح بإرسال رسائل أو تغيير مخارج خارج بيئة الاختبار دون تفويض صريح.

## مصفوفة الاختبار

| الرمز | السيناريو | معيار النجاح | حالة غياب المتطلب |
|---|---|---|---|
| DK-01 | قراءة مواصفات البيئة | تُحفظ هوية البيئة والمدخلات والمخرجات المعلنة | `ABSTAIN` |
| DK-02 | اكتشاف منفذ دخل وخرج | يُكتشف المنفذ دون فتحه أو تغييره | `BLOCKED` عند غياب الصلاحية |
| DK-03 | إعلان محلي | رسالة اختبار موثقة ومصرح بها فقط | `ABSTAIN` إذا تعذر التحقق |
| DK-04 | منع الإعلان غير المصرح | لا تخرج أي حزمة أو إشارة | `FAIL` إذا ثبت الخروج |
| DK-05 | تفويض GPIO أو مخْرج | الانتقال يحدث بعد تفويض وبحدود زمنية | `ABSTAIN` دون عتاد I/O |
| DK-06 | البحث عن خوارزمية | لا قبول تلقائي؛ كل مصدر وبصمة وتبعية مسجلة | `ABSTAIN` عند مصدر مجهول |
| DK-07 | عزل خوارزمية | لا أسرار ولا شبكة ولا كتابة خارج المساحة | `FAIL` عند خرق قابل للإثبات |
| DK-08 | تنسيق نواتين | ترتيب الرسائل وسجل التعارض قابلان لإعادة الإنتاج | `ABSTAIN` عند عدم ثبات البيئة |
| DK-09 | فشل نواة | تعزل النواة الفاشلة ولا تمنحها صلاحيات جديدة | `FAIL` عند استمرار الصلاحية خلاف العقد |
| DK-10 | الإلغاء | يتوقف التنفيذ ضمن حد العقد | `ABSTAIN` إذا لم توجد آلية إلغاء |
| DK-11 | ثبات المخرج | المدخلات والبيئة الثابتة تعطي مخرجاً مطابقاً | `ABSTAIN` عند مصادر عشوائية غير مضبوطة |
| DK-12 | سلسلة الأدلة | كل سجل قابل لإعادة الحساب وتطابق البصمات | `BLOCKED` عند تلف السلسلة |

## بروتوكول التنفيذ

يُنشأ دليل مؤقت لكل حالة، وتُسجل نسخة الشيفرة، ونظام التشغيل، والمعمارية، والموارد، والوقت، ورمز الخروج، والمخرجات المنزوعة من الأسرار. تُنفذ الحالات بترتيب ثابت، ويعاد تشغيل الحالات الحتمية ثلاث مرات على الأقل عندما تسمح الموارد. لا تُستخدم نتائج التشغيل لإرسال فعل خارجي حقيقي؛ ويستبدل ذلك بمحول اختبار يسجل الفعل دون تنفيذه.

## الحكم

تكون النتيجة `PASS` فقط عند تحقق معيار الحالة كاملةً وبوجود سجل قابل للمراجعة. ويكون `FAIL` عند إثبات مخالفة للمعيار. ويكون `ABSTAIN` عند نقص الدليل أو غموض البيئة، و`BLOCKED` عند عائق أداة أو صلاحية أو عتاد. لا ترفع نتائج هذه الخطة وحدها مستوى الإثبات الرسمي للنظام كله.

## المتطلبات قبل اختبار العتاد الحقيقي

يلزم جهاز مخصص أو لوحة اختبار موثقة، ومخطط للمداخل والمخارج، وآلية إيقاف مادية أو برمجية، وشبكة اختبار معزولة، وسجل صلاحيات، وخطة استرداد، وموافقة صريحة على أي أثر خارجي. عند غياب أي عنصر جوهري يبقى الاختبار في حالة `PLANNED` أو `ABSTAIN`.

## الأدلة والبصمات

تُحفظ ملفات السيناريو والبيئة والسجل الخام والنتيجة النهائية في دليل المرحلة، ثم تُحسب بصمات SHA-256 بعد اكتمال الكتابة. تُثبت البصمة سلامة السجل، ولا تثبت بمفردها صحة خصائص النواة أو أمانها المطلق.
