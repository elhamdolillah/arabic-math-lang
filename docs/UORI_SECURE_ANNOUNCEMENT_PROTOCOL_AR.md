# بروتوكول UORI للإعلان والتواصل الآمن

**الحالة:** `PLANNED_PROTOCOL` — مواصفة قابلة للاختبار، وليست دليلاً على اتصال فعلي أو انتشار عالمي.

## 1. المبدأ

لا تعلن نواة UORI عن وجودها ولا ترسل `ping` ولا رسالة نصية أو صوتية أو مرئية ولا تغيّر خرج IoT من صفر إلى واحد لمجرد اكتشاف قناة. الإعلان فعل خارجي يحتاج إلى تفويض صريح، وهوية قابلة للتحقق، ونطاق محدد، وحد أثر، ومهلة، وآلية إلغاء، وسجل دليل. عند نقص أي عنصر جوهري تتوقف النواة وتكتب `ABSTAIN` أو `BLOCKED`.

## 2. حالات النواة

| الحالة | المسموح | الممنوع |
|---|---|---|
| `DISCOVER_ONLY` | قراءة وصف العتاد المعلن | الكتابة أو الاتصال الخارجي |
| `WAIT_AUTHORIZATION` | عرض طلب تفويض محلياً | الإعلان الخارجي |
| `AUTHORIZED_LOCAL` | إخراج محلي محدود | الشبكة أو IoT بلا تفويض إضافي |
| `AUTHORIZED_EXTERNAL` | قناة محددة ومدة محددة | قناة أخرى أو أثر أوسع |
| `RUNNING_REVERSIBLE` | تشغيل موائم مراقب | تجاوز العقد أو الموارد |
| `ABSTAIN` | تسجيل السبب وإتاحة المراجعة | أي فعل خارجي |
| `BLOCKED` | عزل المصدر أو الموائم | إعادة المحاولة غير المصرح بها |

## 3. بنية رسالة الإعلان

كل إعلان قابل للإرسال يمثل سجلاً منظمًا يحتوي على `protocol_version`، و`node_id`، و`device_class`، و`capability_summary`، و`channel`، و`purpose_hypothesis` الموسومة كفرضية، و`authorization_ref`، و`expiry`، و`nonce`، و`effect_limit`، و`cancel_ref`، و`evidence_ref`، و`digest`. لا يضاف سر أو مفتاح خاص أو بيانات مستخدم غير لازمة. ويجب أن تفشل الرسالة إذا تغير أي حقل بعد حساب البصمة.

## 4. اختيار القناة

تختار النواة أقل قناة تحقق الغرض بأقل أثر. الأولوية المقترحة هي العرض المحلي، ثم رسالة نصية مصرح بها، ثم إشارة شبكة محدودة، ثم الصوت أو الصورة عند الحاجة المعلنة، ثم خرج IoT بعد تفويض مستقل. لا تعني أولوية القناة أنها تُنفذ تلقائياً؛ بل هي ترتيب مقترح داخل عقد التفويض.

## 5. التواصل بين الأنوية

يجب أن تحتوي الرسالة بين نواتين على هوية المرسل والوجهة، ورقم تسلسلي، ونافذة صلاحية، ونوع العملية، وبصمة المحتوى، وإثبات التفويض، وآلية منع إعادة الإرسال. تُرفض الرسائل المجهولة أو المنتهية أو المتعارضة مع سياسة الجهاز. لا توجد ثقة ضمنية لمجرد أن الرسالة جاءت من نواة أخرى.

## 6. الإلغاء والفشل

يكون الإلغاء ممكناً قبل التنفيذ وأثناءه متى كان ذلك متوافقاً مع خصائص الجهاز. عند فقد القناة أو انتهاء المهلة أو تغير وصف العتاد أو تجاوز الموارد، يوقف الموائم ويعاد الجهاز إلى آخر حالة آمنة معروفة إن كان ذلك مثبتاً. إذا لم تكن العودة الآمنة مثبتة، تمتنع النواة عن الادعاء بأنها أعادت الحالة وتكتفي بتسجيل `ABSTAIN`.

## 7. سجل الدليل

يسجل كل انتقال حالة: الزمن، الحالة السابقة، الحالة اللاحقة، الحدث، هوية المنفذ، مرجع التفويض، النتيجة، رمز الخطأ، وبصمة المخرجات. ترتبط السجلات بسلسلة SHA-256؛ ولا تُعد البصمة دليلاً على صحة الفعل نفسه، بل دليلاً على سلامة السجل بعد إنشائه.

## 8. اختبارات القبول

| الاختبار | النتيجة المطلوبة |
|---|---|
| اكتشاف جهاز بلا تفويض | لا إعلان، والحكم `ABSTAIN` |
| تفويض نصي محلي محدود | إعلان محلي فقط ضمن المهلة |
| تغيير القناة بعد التفويض | رفض العملية |
| رسالة نواة منتهية | رفض ومنع إعادة الإرسال |
| فقد الشبكة أثناء الإعلان | توقف آمن وسجل السبب |
| طلب IoT بلا عقد إلغاء | `BLOCKED` |
| رسالة تحتوي سراً | رفض وعدم إعادة بثها |
| تغير بصمة الرسالة | رفض التحقق |

## 9. حدود الإثبات

هذه المواصفة لا تثبت اتصال UORI بأي جهاز أو مستخدم أو مستودع إنترنت. يلزم لكل قناة اختبار مستقل على جهاز محدد مع سجل الأمر والبيئة ورمز الخروج والمخرج والبصمة. كما أن وصف UORI بأنه غير مركزي أو موجود في كل مكان يظل وصفاً معمارياً مستهدفاً إلى أن تُثبت هوية الأنوية، واتصالها، وتحمّلها للفشل، وسلامة التنسيق في تجارب فعلية.
