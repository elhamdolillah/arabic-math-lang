# تقرير التحقق العددي لـ C40 و Q32.32

> **الحالة:** نتائج بحث واختبارات قابلة لإعادة الإنتاج. لا تمثل هذه الوثيقة دمجًا لإصلاح داخل النواة، ولا تزعم اكتمال التحقق الرسمي أو العتادي الكامل.

## الملخص

كان العطل الأول في الدالة العربية `أُس` ناتجًا عن غياب معالجة السالب الأحادي في محلل العوامل. أُصلح ذلك داخل worktree معزول، ونجح اختبار إعادة الإنتاج في `8/8` حالات، مع بقاء المصدر الأصلي دون تغيير.

أظهر اختبار الإجهاد الحتمي لـQ32.32 أن تنفيذ `exp` القديم ينجح في `17/21` حالة ويفشل في أربع حالات موجبة كبيرة. ترجع الفروق إلى تقريب `exp(r)` إلى Q32.32 قبل تطبيق عامل `2^k`، مما يضخم الخطأ عند `k=23` و`k=31`. لذلك لم يُعتمد الدمج.

## نتائج خط الأساس

| البوابة | النتيجة |
|---|---:|
| اختبار إعادة إنتاج C40 | `8/8` ناجح |
| اختبار إجهاد Q32.32 | `17/21` ناجح |
| الحالات الفاشلة | `4، 8، 16، 21.4` |
| أقصى فرق مطلق | `12,484,349,952` وحدة Q32.32 |
| أقصى فرق نسبي | `1.477e-9` |
| حالة المصدر الأصلي | لم يتغير |
| قرار الدمج | مرفوض حتى إصلاح الدقة |

## تشخيص الدقة

التقليل الرياضي للمجال هو:

```text
x = k·ln(2) + r
exp(x) = 2^k · exp(r)
```

في التنفيذ القديم كانت قيمة `exp(r)` تُقرّب إلى Q32.32 قبل تطبيق `2^k`. هذا الترتيب غير مناسب لشرط الخطأ المطلق `16`، لأن خطأ التقريب السابق يُضخم بعد التحجيم.

| الإدخال | `k` التقريبي | الفرق المرصود بوحدة Q32.32 |
|---:|---:|---:|
| `4` | `6` | `78` |
| `8` | `12` | `7,046` |
| `16` | `23` | `37,748,992` |
| `21.4` | `31` | `12,484,349,952` |

## النموذج المصحح

اختُبر نموذج Q64.64 داخليًا، مع رفع الإدخال من Q32.32 إلى Q64.64، وإبقاء Horner والتحجيم في الدقة الداخلية، ثم التقريب مرة واحدة إلى Q32.32 في النهاية. في المجال الاختباري:

| الإدخال المكمم | الفرق النموذجي |
|---:|---:|
| `0، 1، 4، 8، 16` | `0` |
| `21.4` | `-3` |
| `-1، -4، -8، -16، -21.4` | `0` |

القيم السابقة نتيجة نموذج Python عالي الدقة، وليست بعدُ نتيجة مولّد النواة الكامل.

## التحقق العتادي الجزئي

اختُبرت عملية الضرب المختلط في NASM على x86_64 مقابل مرجع C يستخدم `__int128`:

```text
MIXED_ASM_CASES=10016
MIXED_ASM=PASS
```

غطى الاختبار حالات الإشارة، وaccumulator يتجاوز signed 64-bit، وقائمة حتمية من 10,000 حالة. أضيفت كذلك علامة `.note.GNU-stack` لمنع إنشاء مكدس قابل للتنفيذ.

## بوابة النشر

أُنشئت بوابة تحقق دورية تعمل داخل worktree معزول، وتتحقق من مساحة القرص، وصياغة Python، واختبارات C40، ووجود Git metadata، وتحفظ تقريرًا لكل دورة. المؤقت الدوري يعمل، ولا ينفذ الدمج تلقائيًا.

آخر حالة تشغيل موثقة:

```text
DISK=88%
GIT_METADATA=absent; source-only worktree; Git diff checks skipped
RC_c40_q32_stress=1
STATUS=مرفوض
MERGE=not-performed
```

## حدود النتيجة

لا يجوز اعتبار نموذج Q64.64 أو اختبار الضرب المختلط برهانًا رسميًا كاملًا للنواة. ما زال يلزم دمج مسار Horner في مولّد Assembly، ثم تشغيل اختبار الإعادة والإجهاد، واختبار تفاضلي بين WASM وx86_64، والتحقق من حدود overflow وunderflow، قبل أي دمج.

## إعادة الإنتاج

الملفات المرافقة في هذا المجلد تتضمن النماذج، ومواصفة Q1.63/Q64.64، واختبار الضرب المختلط، واختبار NASM، ومشغل بوابة التحقق. جميع الاختبارات حتمية ولا تعتمد على شبكة أو أسرار أو مفاتيح.

## القرار

التصحيح النحوي للسالب الأحادي مثبت في worktree فقط. أما إصلاح دقة `exp` الموجبة فما زال قيد التطوير. لذلك يُنشر هذا التقرير للاستفادة العلمية وإعادة الاختبار، مع إبقاء الدمج الرسمي مرفوضًا حتى تحقق شرط `abs(فرق) <= 16` في جميع الحالات.
