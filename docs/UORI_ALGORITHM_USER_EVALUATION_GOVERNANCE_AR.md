# تقييمات مستخدمي خوارزميات UORI وحوكمتها

**الحالة:** `GOVERNANCE_SPECIFICATION` — التقييمات دليل تشغيلي مكمل، وليست برهاناً مستقلاً على السلامة أو الكفاءة.

## المبدأ

يستطيع مستخدمو UORI تقييم الخوارزمية التي استعملوها، لكن التقييم يرتبط دائماً بـ`algorithm_id` والإصدار والبصمة والبيئة والغرض. ولا يجوز دمج تقييمات إصدارات مختلفة في درجة واحدة توهم بأن الإصدار الحالي اختُبر بما لم يُختبر به.

## بطاقة التقييم

| الحقل | المضمون |
|---|---|
| معرف الخوارزمية والإصدار | تحديد المادة المقيمة |
| بصمة الإصدار | منع إسناد التقييم إلى نسخة أخرى |
| سياق الاستخدام | العتاد والبيئة والغرض |
| نوع الملاحظة | منفعة أو قابلية استعمال أو أداء أو عطل أو خطر |
| الوصف القابل لإعادة الإنتاج | خطوات ومداخل ومخرجات دون أسرار |
| شدة الأثر | منخفض، متوسط، عالٍ، حرج |
| دليل مرفق | سجل أو لقطة أو اختبار أو مرجع |
| زمن التقييم | الترتيب الزمني للحالة |
| حالة المراجعة | جديد، مؤكد، مكرر، محل نزاع، مغلق |

## فصل التقييم عن القبول

لا يرفع متوسط التقييم حالة الخوارزمية إلى `ADMITTED` أو `PROVEN`. يمكن لتقييم إيجابي أن يشير إلى منفعة أو سهولة استعمال، ويمكن لتقييم سلبي أن يفتح تحقيقاً أو يوقف الإصدار احترازياً، لكن قرار السلامة يعتمد على الاختبارات والأدلة والعقد. كما لا يكفي عدد المستخدمين لإثبات غياب الضرر على كل إنسان أو عتاد أو بيئة.

## منع التلاعب وحماية المستخدم

تمنع الحوكمة التقييمات المكررة آلياً، وتفصل هوية المستخدم عن النص المنشور عند الحاجة، وتمنع نشر أسرار أو بيانات شخصية أو تعليمات ضارة. ولا تستخدم التقييمات لاتخاذ قرار آلي مؤثر على شخص دون مراجعة وسياسة معلنة. ويجب تسجيل تعديلات التقييم وحالات حذفه وسببها وبصمة السجل.

## قناة البلاغات الحرجة

إذا أبلغ مستخدم عن ضرر أو سلوك غير متوقع، يوسم الإصدار فوراً بـ`REVIEW_REQUIRED`، ويوقف النشر المؤثر أو يخفض صلاحياته عند الإمكان، ويحفظ الدليل الخام، ويطلب إعادة الإنتاج في عزل. ولا يحسم البلاغ بأنه صحيح أو كاذب قبل الفحص؛ فإذا تعذر الحكم تبقى الحالة `ABSTAIN`.

## مؤشرات العرض

تعرض المنصة عدد التقييمات، وتوزيعها، ونطاق البيئات، ونسبة التقييمات المؤكدة أو المتنازع عليها، وتاريخ آخر مراجعة. ولا تعرض رقماً واحداً بوصفه «درجة أمان مطلقة». ويجب تمييز الرأي البشري، والقياس التجريبي، والبرهان الرسمي بألوان وحالات مستقلة في السجل والواجهة.

## علاقة التقييمات بالأدلة

يمكن أن ينتج عن التقييم طلب اختبار جديد أو تحديث لعقد الإصدار. وعند تأكيد ملاحظة، يربط سجلها بسلسلة SHA-256 ويحدث حالة الإصدار أو يفتح إصدار إصلاح جديد. أما الادعاءات غير القابلة للتحقق فتظل ملاحظات غير محسومة ولا تستخدم لرفع حالة القبول.

## الحكم

`PASS_USER_EVALUATION_GOVERNANCE_WITH_NON_PROOF_STATUS`.
