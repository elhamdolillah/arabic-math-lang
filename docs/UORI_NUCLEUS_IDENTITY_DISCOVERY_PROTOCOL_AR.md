# هوية نواة UORI واكتشافها وبروتوكول الاتصال

## 1. الغرض

يحدد هذا المستند كيف تعلن نواة UORI عن وجودها، وكيف تكتشف نظائرها، وكيف تتحقق من العضوية قبل تبادل الأعمال أو البيانات. لا يكفي وصول رسالة أو ظهور عنوان شبكي لإثبات أن الطرف نواة UORI؛ فالعضوية عقد موقّع مرتبط بمعرف وإصدار وبصمة ونطاق صلاحيات.

## 2. سجل هوية النواة

| الحقل | الوصف |
|---|---|
| `nucleus_id` | معرف ثابت للنواة أو لمثيلها التشغيلي |
| `kernel_version` | إصدار نواة UORI |
| `image_hash` | بصمة الصورة التنفيذية أو الحزمة المعتمدة |
| `hardware_scope` | العتاد أو البيئة التي تعمل فيها النواة |
| `capability_manifest` | القدرات المكتشفة، مع تمييز المرشح من المثبت |
| `protocols` | قنوات الاتصال التي ثبت دعمها |
| `policy_version` | نسخة الدستور وسياسة الصلاحيات |
| `attestation` | شهادة أو سجل يثبت حالة التشغيل ضمن نطاقه |
| `revocation_state` | حالة الإلغاء أو التعليق |
| `evidence_chain` | روابط الأدلة وبصمات SHA-256 |

## 3. دورة الإعلان والاكتشاف

تبدأ النواة برسالة إعلان محدودة لا تحتوي على أسرار ولا تمنح وصولاً تلقائياً. تتضمن الرسالة المعرف والإصدار والبصمة ونطاق القدرات والقناة المطلوبة وسياسة التحقق. تستقبل النواة النظيرة الرسالة في حالة غير موثقة، ثم تتحقق من البصمة والتوقيع وحالة الإلغاء، وتطلب تحدياً عشوائياً أو دليلاً قابلاً للإعادة قبل إنشاء جلسة.

| الحالة | معنى الرسالة | الإجراء |
|---|---|---|
| `SEEN` | شوهد إعلان غير موثق | تسجيل فقط |
| `IDENTITY_CHECK` | يجري فحص الهوية والبصمة | لا بيانات حساسة |
| `MEMBERSHIP_PENDING` | الهوية معروفة لكن العضوية غير مكتملة | عزل القناة |
| `ADMITTED` | اجتاز الطرف شروط العضوية ضمن نطاق محدد | جلسة محدودة |
| `SUSPENDED` | انتهت الصلاحية أو ظهر تعارض | إيقاف الجلسة |
| `REVOKED` | أُلغي الاعتماد | منع وإبلاغ الخلية |

## 4. عقد الاتصال

كل جلسة تحتاج إلى عقد يحدد الطرفين، والهدف، والرسائل المسموح بها، ومدة الصلاحية، وحدود المعدل والحجم، وحق الإلغاء، وسجل النتائج. لا يجوز تحويل قناة إعلان إلى قناة تنفيذ. ولا يجوز لنواة أن تطلب من نواة أخرى تحميل خوارزمية أو تنفيذ عملية عتادية إلا عبر بوابة القبول والتفويض.

## 5. التحقق من العضوية

العضوية لا تستنتج من الاسم أو عنوان الشبكة أو الموقع الجغرافي. ويجب أن ترتبط بمعرف النواة وبصمة الإصدار وبالدليل المتاح. إذا تعذر التحقق من أي عنصر، تعود الحالة إلى `ABSTAIN` أو `MEMBERSHIP_PENDING`، وتظل الخدمات الحساسة معزولة. وتُسجل جميع عمليات القبول والرفض والإلغاء في سجل غير قابل للالتباس، مع بصمة كل رسالة ونتيجة القرار.

## 6. نمط الاتصال اللامركزي

لا تفترض UORI خادماً مركزياً وحيداً لتوزيع العضوية أو الأعمال. يمكن للخلايا تبادل سجلات عضوية موقعة، ويمكن للنواة أن تعمل محلياً عند غياب النظائر. وعند عودة الاتصال، تُقارن السجلات بحسب أرقام الإصدارات والبصمات وأزمنة الحدث، ويُحال التعارض إلى سياسة حتمية أو فترية أو احتمالية معلنة، مع الامتناع عند عدم كفاية القاعدة.

## 7. حدود الحالة

هذا المستند يعرّف بروتوكولاً معمارياً مقترحاً. لا يثبت وجود شبكة UORI عالمية أو عدد محدد من الأنوية أو تحققاً تشغيلياً من العضوية عبر الإنترنت. تثبت هذه الأمور فقط باختبارات موزعة، وسجلات تشغيل، وبصمات، وقياسات قابلة لإعادة الإنتاج.

**الحالة:** `PLANNED_ARCHITECTURE`.
