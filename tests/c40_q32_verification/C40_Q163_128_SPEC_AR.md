# مواصفة إصلاح C40: exp بدقة Q1.63 وحاصل 128-bit

## الحالة

هذه مواصفة تصميم للنسخة المعزولة فقط. لا تغيّر `/home/uori-agent/lib/math_complete.py` ولا تسمح بالدمج قبل اجتياز الاختبارات.

## التمثيل

تُحوَّل قيمة الإدخال Q32.32 إلى Q1.63 عبر:

```text
x63 = x32 << 31
```

وتُحفظ معاملات الحساب الوسيط في سجلات صحيحة موقعة. قيمة الناتج العام تبقى Q32.32.

الثوابت عالية الدقة:

```text
LN2_Q63     = 6393154322601327830
INV_LN2_Q63 = 13306513097844322492
```

## تقليل المجال

```text
k = round(x63 * INV_LN2_Q63 / 2^126)
r = x63 - k * LN2_Q63
```

يجب تنفيذ حاصل ضرب `x63 * INV_LN2_Q63` كحاصل signed 64×64 ينتج زوج `RDX:RAX`، لأن حاصل الضرب مقياسه Q2.126. لا يجوز إسقاط الجزء العالي أو استخدام Q32.32 في هذه المرحلة.

## Horner

تستخدم `exp(r)` متسلسلة Taylor من الدرجة 12 بمعاملات مولدة مباشرة في Q1.63:

```text
c_n = round(2^63 / n!)
```

لكل خطوة:

```text
acc = floor((r * acc) / 2^63) + c
```

ويجب تنفيذ الضرب كـ128-bit ثم إجراء إزاحة حسابية 63 بت. لا يجوز تحويل `acc` إلى Q32.32 أثناء Horner.

## التحجيم النهائي

الترتيب الإلزامي:

```text
scaled_Q63 = exp_r * 2^k
output_Q32 = round(scaled_Q63 / 2^31)
```

أي أن `2^k` يُطبَّق قبل التحويل النهائي إلى Q32.32. هذا يمنع تضخيم خطأ تقريبي مبكر عند `k=23` و`k=31`.

## حدود السلامة

القيمة الموجبة القصوى المختبرة عند `x≈21.4` تعطي ناتجًا Q32.32 يقارب `8.45e18`، وهو داخل مجال signed 64-bit. أما ناتج Q1.63 قبل التحويل النهائي وبعد التحجيم فيجب حفظه في 128-bit؛ لا يكفي signed 64-bit.

قبل التحويل النهائي يجب فحص overflow. عند تجاوز المجال، يعاد رمز خطأ حتمي ولا يسمح بالالتفاف الصامت.

## خصائص الاختبار الإلزامية

| الخاصية | الشرط |
|---|---|
| الصفر | `exp(0)=1` في Q32.32 |
| التماثل العددي | كل حالات السالب الأساسية لا تتراجع |
| الإعادة | `8/8` ناجح |
| الإجهاد | `21/21` ناجح، و`abs(فرق)<=16` |
| المجال | لا overflow صامت عند `k=31` |
| التفاضل | تطابق نموذج Decimal عند استخدام الإدخال المكمم |
| الأصل | SHA-256 للنسخة الأصلية لا يتغير |
| الدمج | لا commit ولا merge قبل اكتمال جميع الشروط |
