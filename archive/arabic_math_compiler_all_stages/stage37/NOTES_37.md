## الجذر السببي

`ن=="مقارنة"` (math_complete.py سطر ~469):
```
code=left+["    push rax"]+right+["    pop rbx"]
code.append("    cmp rbx, rax")  ← مقارنة عناوين فقط!
```
- نص حرفي (ن=="نص") يُخزَّن في arena كسلسلة [length] [bytes...] كل مرة تُولَّد نسخة جديدة.
- متغير نصي يحمل عنوان السلسلة.
- `نوع = "اسم"` يقارن عنوان المتغير بعنوان نسخة حرفية جديدة → عناوين مختلفة → دائمًا False → counts=0.

الاختبار 1 و4 و5 نجحا لأنهم لا يستخدمون = بين نصين (اختبار 1 يستخدم ≠/حجم/رأس/ذيل، اختبار 4 و5 لا مقارنة نصية).

## الحل

إضافة مقارنة محتوى سلسلة في مسار المقارنة عندما يكون كلا الطرفين نصًا.
لكن النوع الاستنتاجي (استنتاج_نوع) يحدد نص فقط للحرفيات المباشرة، والمتغير نوعه "مجهول" غالبًا.
**الحل الأبسط والأشمل**: في مسار المقارنة، إذا كان op ∈ {=, ≠}:
- إذا كان الطرفان نصيَّين حرفيَّين (ن=="نص" لكليهما): قارن عنوانيًا (سليم، كل حرفي يُخزَّن مرة واحدة؟ لا — كل ترجمة حرفي تنشئ نسخة جديدة من arena... لكن داخل نفس البرنامج كل استخدام "نص" literal يُولِّد نسخة جديدة!).
  - ⚠️ حتى "نوع ≔ رأس(أنواع)" ثم نوع = "اسم": رأس() يُرجع عنوان السلسلة المخزنة في قائمة (نسخة واحدة)، و"اسم" الحرفي نسخة جديدة → عناوين مختلفة.
- لذا الحل الصحيح: مقارنة محتوى (byte-wise) بين [ptr1] و[ptr2] كسلسلة، بطول min(len1,len2) ثم مقارنة الأطوال.

### تنفيذ مقارنة سلسلة (runtime helper str_eq):
```
str_eq:
  ; rax = ptr1, rbx = ptr2
  mov rcx, [rax]       ; len1
  mov rdx, [rbx]       ; len2
  cmp rcx, rdx
  jne .neq
  ; loop bytes
  mov rsi, rax
  mov rdi, rbx
.loop:
  test rcx, rcx
  jz .eq
  mov al, [rsi]
  cmp al, [rdi]
  jne .neq
  inc rsi; inc rdi; dec rcx
  jmp .loop
.eq:
  mov rax, 1
  ret
.neq:
  mov rax, 0
  ret
```

في compile_program يجب التحقق من وجود string literals أو مقارنة نصية قبل تضمين helper.

### التعديل في مسار المقارنة:
- بعد left+push+right+pop: لدينا rax = right, rbx = left.
- إذا كان expr[2] نص أو expr[3] نص أو طرف متغير من نوع نص: قارن عنوانيًا أولًا؛ إذا متساويان → 1، وإلا استدعِ str_eq.
- للتبسيط الشامل: دائمًا (عند op = أو ≠):
  - cmp rbx, rax; je equal
  - else: call str_eq... لكن str_eq يفسد regs؟ يجب حفظ args:
  ```

  je .se_eq_k

  mov rdx, [rsp]   ; NO — stack layout after pushes
  ```

  ```

  ```
  سأكتبه في الكود مباشرة بعد التحقق التجريبي.

## ملاحظة
استنتاج_نوع للمتغير قد يكون "مجهول" — لا يمكن الاعتماد عليه. الحل: مقارنة نصية عندما يكون **أي** طرف نص حرفي، أو طرف متغير/استدعاء. لكن مقارنة عددين كنص ستعطي نتيجة خاطئة!
- هل المقارنة العددية كنص تؤذي؟ عدديْن: [0..7] ليست length صالحًا بالضرورة لكنها سلاسل... مقارنة عناوين أولًا fail (أرقام لا تخزَّن كنص). ثم str_eq على قيم عشوائية → نتيجة خاطئة محتملة.
- **آمن**: فقط إذا expr[2] أو expr[3] نوعه "نص" أو هو نص حرفي (ن=="نص") → مسار نصي. متغير مع نوع "نص" يُدخَل مسار نصي أيضًا (نوع س = رأس(قائمة نصية) → استنتاج: متغير "مجهول"!).
- بديل: إضافة نوع "نص" صريح عبر type_env عند النقل من نص — لكن استنتاج_نوع لـ"نقل": `type_env[بيان[1]] = type_env.get(بيان[2], "مجهول")` — رأس()؟ استنتاج_نوع لـ استدعاء رأس: "قائمة" فقط... غير دقيق.
- **عملي**: عند نقل متغير يساوي نص حرفي (type_env[اسم] قد لا يكون نص). الحل العملي: عند op ∈ {=,≠} إذا كان أي طرف ن=="نص" (حرفي) → مسار نصي؛ وأيضًا إذا كان أي طرف متغير/استدعاء وكان الطرف الآخر نص حرفي → نصي (مخاطرة: إذا كان المتغير عدديًا! نوع = رأس(أنواع) نص لكن متغير عام مثل صحيحة عدد — صحيحة = 0 لا يمرر عبر نص حرفي، الطرفان عدديان → لا نص حرفي → مسار عددي سليم).
  - الحالة الوحيدة الخطرة: متغير نصي = آخر نصي (لا حرفي في المقارنة): مثل `حالة1 = حالة2` كلاهما متغير نصي — غير مستخدم في stage 37. نعالجه: إذا أي طرف متغير نَوعُه في type_env == "نص" → نصي أيضًا.
  - نوع رأس(قائمة نصية) في استنتاج_نوع: استدعاء رأس → "قائمة"! سيعطي مسار عددي خاطئًا لو قارنا رأس(قائمة) بنص حرفي. لكن حالة السكربت: نوع ≔ رأس(أنواع) ثم نوع = "اسم" → الطرفان: متغير نوع = رأس(أنواع) (ن=="استدعاء" رأس → نوع استنتاجي "قائمة") + نص حرفي "اسم" (ن=="نص") → يوجد حرفي نصي → مسار نصي ✓.

## القرار
عند op ∈ {=,≠}: إذا أي طرف ن=="نص" (حرفي) → مسار مقارنة نصية (call str_eq مع مساواة عنوانية أولًا). وإلا → مسار عددي الحالي.
