# المراجعة الدستورية المصححة لمقترح مشغل MAL

**التاريخ:** 2026-08-25  
**النطاق:** تقييم الملف `pasted_content.txt` بوصفه مقترحًا لسد فجوة تنفيذ ملفات `.ar`  
**المرجع المجمد:** `MAL_RUNTIME_EXECUTION_GATE_REPORT_2026-08-25_AR.md`  
**حالة baseline:** مجمدة ولم تُعدّل

## 1. الحكم التنفيذي

المقترح **ليس مشغلًا موثوقًا للغة MAL**، ولا يثبت سد فجوة التنفيذ. وهو صالح فقط بوصفه **مسودة بحثية غير قابلة للدمج** لفكرة واجهة تشغيل مستقبلية. السبب الحاسم أن الشيفرة المقترحة لا تحتوي محللًا نحويًا أو مفسرًا أو منفذًا لدلالة MAL؛ بل تقرأ النص، تبحث عن كلمات محددة، وتزيد عدادًا افتراضيًا للعقد ثم تعيد `Ok(0)`. لذلك فإن نجاحها، لو أمكن بناؤها، لا يعني تنفيذ ملف `.ar` ولا إنتاج AST أو IR أو ABI أو مخرجات قابلة للمقارنة.

القرار الدستوري هو:

```text
CONSTITUTION_REVIEW=PASS_WITH_GUARDS
PROPOSED_RUNNER_STATUS=ABSTAIN
RULES_EXECUTIVELY_ADOPTED=0
MAL_AR_RUNTIME=UNAVAILABLE
SOURCE_EXECUTION=NOT_PERFORMED
DIFFERENTIAL_EXECUTION=NOT_PERFORMED
SIDECAR_FINGERPRINTING=NOT_PERFORMED
AUTO_PROMOTION=DENY
BASELINE_FREEZE=ACTIVE
```

## 2. الأدلة المحلية المفحوصة

| الدليل | النتيجة ذات الصلة |
|---|---|
| `pasted_content.txt` | يقترح مشغلًا بلغة Rust مع فحص نصي محدود وخطوات بناء Bash |
| `rust/mal_ownership_arena/src/lib.rs` | مكتبة Arena حتمية محليًا، بلا `unsafe`، ولا تحتوي محلل MAL أو مفسرًا أو دالة `allocate_node` |
| `audit/MAL_RUNTIME_EXECUTION_GATE_REPORT_2026-08-25_AR.md` | يثبت أن المشغل السابق غير متاح وأن تنفيذ `.ar` لم يُجرَ |
| `rust/mal_ownership_arena/Cargo.toml` | غير موجود في الشجرة المفحوصة؛ لذلك لا يوجد دليل على crate قابل للبناء بالمواصفة المقترحة |

لم تُنفذ الشيفرة الواردة في الملف؛ لأن التنفيذ لا يجوز قبل اجتياز بوابة التفويض البنيوي، ولأن التقييم الساكن كشف عدم توافق واجهات جوهريًا.

## 3. فحص قابلية البناء والواجهات

المقترح يستدعي:

```rust
let mut arena = Arena::new(1024);
arena.allocate_node()
```

لكن الواجهة الفعلية في `lib.rs` هي:

```rust
pub fn new(arena_id: u32, owner_scope: u32, capacity: usize)
```

والتخصيص الفعلي هو:

```rust
pub fn allocate(&mut self, value: T, type_tag: u32)
```

ولا توجد دالة باسم `allocate_node`. وعليه فالمقترح **لا يطابق API الموجود**، ولا يمكن اعتباره حتى مشغلًا تجريبيًا قابلًا للبناء قبل إضافة عقد وواجهات جديدة. كما أن عدم وجود `Cargo.toml` في المسار المفحوص يمنع إثبات أمر `cargo build --release --bin mal_runner`.

## 4. التقييم الدستوري التفصيلي

| الادعاء أو المكوّن | التقييم | السبب |
|---|---|---|
| منع `unsafe` | `POLICY` | الملف يذكر المنع، ومكتبة Arena تحتوي `forbid(unsafe_code)`، لكن ذلك لا يثبت دلالة المشغل ولا عزله الكامل |
| استخدام Arena/NodeID | `RESEARCH` | المقترح لا يبني عقد MAL فعلية ولا يعيد `NodeID` موثقًا؛ استدعاء `allocate_node` غير موجود |
| التنفيذ الحتمي | `ABSTAIN` | لا توجد خوارزمية تفسير أو ترتيب دلالي أو عقد canonical أو corpus يثبت التكافؤ |
| فحص `eval` و`exec` نصيًا | `POLICY` محدود | الفحص النصي ليس فحص AST، ويمكن أن يفوّت صيغًا أو يرفض نصوصًا سليمة؛ لا يثبت منع التنفيذ الديناميكي |
| منع التخصيص الديناميكي | `ABSTAIN` | `Vec` داخل Arena، و`String`، و`read_to_string` تعتمد على تخصيصات وقت التشغيل؛ لا يوجد عقد يثبت أنها مسموحة أو محكومة ضمن نموذج المشروع |
| العزل الشبكي | `ABSTAIN` | لا يوجد sandbox أو سياسة نظام أو اختبار يثبت تعطيل الشبكة |
| ثبات البصمة | `ABSTAIN` | بصمة الثنائي وحدها لا تثبت ثبات مخرجات التنفيذ، كما لم تُحفظ مخرجات خام أو سلسلة تحقق |
| `SOURCE_EXECUTION=PERFORMED` | `DENY` | لا يوجد تشغيل ناجح موثق لملف `.ar` بواسطة مفسر MAL |
| `AUTO_PROMOTION=ALLOW` | `DENY` | مخالف لشرط corpus والتكافؤ الثنائي والبصمات المستقلة |

## 5. العيوب التي تمنع سد فجوة التنفيذ

### أ. لا يوجد تفسير للغة

الدالة `execute_mal_source` لا تفهم بنية MAL. فهي تتجاوز الأسطر الفارغة والتعليقات، ثم تبحث عن السلسلتين `NodeID` أو `بنية_`. هذا ليس تحليلًا معجميًا أو نحويًا، ولا يتحقق من التراكيب أو الأنواع أو النطاق أو ترتيب العمليات أو دلالات Arena. الملف الذي لا يحتوي هذه الكلمات سيُقبل بنتيجة صفرية، والملف الذي يحتويها سيُعامل كما لو أنه نفّذ عقدة؛ وهذه علاقة غير صحيحة بين المصدر والتنفيذ.

### ب. لا توجد مخرجات دلالية قابلة للمقارنة

المشغل المقترح لا يصدر AST canonical، ولا IR، ولا سجل تعليمات، ولا ABI، ولا stdout معياريًا مستقلًا عن المسار. لذلك لا يمكن استخراج sidecar حقيقي ولا إجراء Differential Execution Test مقابل Python.

### ج. ادعاء الحتمية غير مكتمل

تركيب `fs::read_to_string` وقراءة المسار وإظهار المسار ورسائل أخطاء النظام يجعل الخرج تابعًا للبيئة والمسار ونص الخطأ. حتى لو كانت القراءة نفسها حتمية لمحتوى ثابت، فلا توجد مواصفة canonical للترميز، أو تطبيع لنهايات الأسطر، أو سياسة للـ Unicode، أو حدود وقود، أو مخرجات مستقلة عن البيئة. كما أن `cargo build --release` لم يُربط بإعدادات إعادة إنتاج كاملة.

### د. خرق مسار السيادة المطلقة

المقترح يضيف منطقًا جوهريًا بلغة Rust، ويقترح سكريبت Bash. وبحسب قاعدة السيادة المطلقة، لا يجوز اعتماد ذلك كحل نواة إلا بعد تبرير الضرورة القصوى وموافقة صريحة على جسر مؤقت، أو بعد تطوير بدائيات MAL اللازمة أولًا. الملف لم يقدم بوابة تفويض من هذا النوع؛ لذلك يبقى الجسر غير معتمد.

### هـ. الانتقال غير المصرح به للحالات

النص يقرر أن المؤشرات ستتحول تلقائيًا إلى `SOURCE_EXECUTION=PERFORMED` و`AUTO_PROMOTION=ALLOW` بمجرد بناء الثنائي وتشغيله. هذا غير صحيح دستوريًا. بناء ثنائي أو تشغيل فحص شكلي لا يحقق شروط الترفيع. القرار يجب أن ينتج من أدلة مستقلة: corpus محفوظ، stdout/stderr خام، بصمات، تحقق سلسلة، ومقارنة ثنائية ناجحة.

## 6. ما يمكن الاحتفاظ به من المقترح

يمكن حفظ الفكرة في فرع بحثي فقط، بعد تصحيح وصفها إلى **مغلف تشغيل تجريبي غير موثوق**. العناصر القابلة لإعادة الاستخدام هي تحديد واجهة CLI، والتحقق الأولي من امتداد `.ar`، ووضع مبدأ الامتناع عند الخطأ. ولا يجوز استخدام هذه العناصر لإعلان توفر `MAL_AR_RUNTIME` أو لترفيع الوحدات.

## 7. المتطلبات الدنيا للمشغل الحقيقي

قبل أي تغيير في baseline، يجب أن يحقق المشغل ما يأتي داخل امتداد مستقل:

| البند | شرط القبول |
|---|---|
| القراءة | قبول UTF-8 canonical ورفض المدخل غير المعياري صراحةً |
| التحليل | lexer/parser حقيقيان يعيدان AST بعقد Arena و`NodeID` محدود |
| التفويض | فحص AST يمنع `eval` و`exec` والاستيراد والمسارات غير المصرح بها |
| الدلالة | تنفيذ مجموعة MAL محددة بعقد وأنواع وحدود وفشل معلنة |
| الترتيب | ترتيب canonical ثابت ومستقل عن النظام أو الجدولة |
| الوقود | حد تنفيذ ثابت، ومع نفاده تكون النتيجة `ABSTAIN` |
| المخرجات | stdout canonical لا يتضمن مسارات أو رسائل بيئية متغيرة |
| corpus | حالات موجبة وسالبة، تشمل المعرف الصفري، تجاوز السعة، عدم تطابق النوع، والترتيب غير المعياري |
| الإثبات | stdout خام، SHA-256، وسلسلة تحقق ناجحة عبر `sha256sum -c` |
| المقارنة | تطابق MAL مقابل Python بتًا ببتًا ضمن نطاق corpus المعلن |
| sidecar | بصمات فعلية للمدخل وAST وIR وABI والمخرج، لا placeholders |

## 8. خطة العمل الآمنة للدفعة التالية

لا تُنفذ الشيفرة المرفقة ولا تُرفع حالتها. تُسجل كـ `RESEARCH/ABSTAIN`، ثم يبدأ العمل في امتداد مستقل على مراحل 77/777/7777 كما يلي: أولًا تعريف عقد ABI للمحلل والـ AST والـ IR دون ادعاء تنفيذ؛ ثانيًا بناء corpus ثابت وسجل stdout متوقع؛ ثالثًا إضافة واجهة Arena مطابقة للعقد الفعلية؛ رابعًا تنفيذ parser محدود النطاق مع حالات امتناع صريحة؛ خامسًا تشغيل اختبارات صغيرة وحفظ المخرجات والبصمات؛ وسادسًا إجراء المقارنة الثنائية قبل أي طلب ترفيع.

إذا تعذر توفير parser أو interpreter أصلي بلغة MAL، فالحالة الصحيحة ليست اختراع قيمة بديلة، بل:

```text
MAL_AR_RUNTIME=UNAVAILABLE
SOURCE_EXECUTION=NOT_PERFORMED
STATUS=ABSTAIN
```

## 9. القرار النهائي

**المقترح مرفوض بوصفه حلًا مكتملًا للفجوة التنفيذية، ومقبول فقط بوصفه مادة بحثية غير مدمجة.** لا يُسمح بتغيير `MAL_AR_RUNTIME` أو `SOURCE_EXECUTION` أو `AUTO_PROMOTION`، ولا بتحديث sidecar أو نسبة الهجرة على أساسه. النجاح المحلي الممكن لمكتبة Arena يظل دليلًا على طبقة الذاكرة وحدها، لا على تشغيل MAL.

### الحالة المعتمدة بعد المراجعة

```text

PROPOSED_RUNNER=ABSTAIN
MAL_AR_RUNTIME=UNAVAILABLE
SOURCE_EXECUTION=NOT_PERFORMED
DIFFERENTIAL_EXECUTION=NOT_PERFORMED

RAW_POINTERS=DENY
DYNAMIC_ALLOCATION=DENY
EVAL_EXEC=DENY
NETWORK=DISABLED_BY_CONTRACT
BASELINE_FREEZE=ACTIVE
AUTO_PROMOTION=DENY
```
