# عقد أثر `بلا_تخصيص` في MAL — الإصدار 0.1

## 1. الحالة والنطاق

هذا الملف عقد بحثي مستقل لتمثيل أثر عدم التخصيص في لغة MAL/UORI. لا يضيف العقد كلمة محجوزة أو سمة نافذة إلى `Grammar v0.1`، ولا يغيّر baseline النواة أو ABI القائم. الغرض هو تحديد دلالة قابلة للفحص تمهيدًا لتنفيذها لاحقًا داخل امتداد مستقل.

```text
CONTRACT=MAL_NO_ALLOCATION_EFFECT_v0.1_AR
STATUS=RESEARCH
GRAMMAR_MODIFIED=NO
KERNEL_BASELINE_MODIFIED=NO
SOURCE_EXECUTION=NOT_PERFORMED
AUTO_PROMOTION=DENY
```

## 2. المفهوم الموحّد

يُسمّى الأثر العربي canonical: **أثر التخصيص**. وله ثلاث قيم مرتبة من الأقل تقييدًا إلى الأكثر خطورة:

| القيمة | المعنى | الحكم في سياق `بلا_تخصيص` |
|---|---|---|
| `ALLOC_NONE` | لا توجد عملية تخصيص أو استدعاء ذي أثر تخصيص معروف | مقبول مبدئيًا |
| `ALLOC_ARENA_ONLY` | استعمال ساحة ثابتة منشأة مسبقًا دون توسيعها أو امتلاك ذاكرة جديدة | مقبول فقط إذا صرّح العقد بالساحة وحدودها |
| `ALLOC_DYNAMIC` | تخصيص ديناميكي، أو استدعاء غير معروف الأثر، أو مسار لا يمكن إثباته | مرفوض حتميًا |

الترتيب ليس قياسًا زمنيًا للأداء، ولا يثبت أن الدالة خالية من الحجب أو المقاطعة أو تغير زمن التنفيذ. العقد يثبت فقط أثر التخصيص المعروف من AST وABI ضمن نطاق الفحص.

## 3. الصيغة المقترحة في MAL

الصيغة المقترحة للامتداد هي سمة عربية، وليست جزءًا من Grammar v0.1 قبل اعتمادها:

```text
دالة بلا_تخصيص اسم_الدالة(المعاملات) {
    جسم_حتمي
}
```

ولأغراض هذا العقد، تُفسَّر السمة كإعلان يتطلب برهانًا، لا كتعليق أو وعد. إذا تعذر تحليل أي عقدة أو استدعاء، يكون القرار `ABSTAIN/UNKNOWN_EFFECT`، ولا يُنتج الملف التنفيذي.

## 4. قواعد الاستدلال

يحسب المحلل أثر كل دالة من عقد AST وفق القواعد التالية:

| قاعدة | أثر النتيجة |
|---|---|
| ثابت، قراءة، حساب صحيح، فرع، أو عودة بقيمة موجودة مسبقًا | لا يرفع الأثر |
| قراءة أو كتابة داخل arena ثابتة معلنة بحدودها | `ALLOC_ARENA_ONLY` |
| استدعاء دالة أثرها `ALLOC_NONE` | يبقى الأثر الحالي |
| استدعاء دالة أثرها `ALLOC_ARENA_ONLY` | الأثر يصبح `ALLOC_ARENA_ONLY` |
| استدعاء دالة أثرها `ALLOC_DYNAMIC` | النتيجة `REJECT/ALLOCATION_EFFECT` |
| استدعاء دالة بلا أثر معروف | `ABSTAIN/UNKNOWN_EFFECT` |
| بدائية أو استيراد أو نداء ABI غير مصنف | `ABSTAIN/UNKNOWN_EFFECT` |
| وجود `eval` أو `exec` أو `source_ref` أو shell أو شبكة | `REJECT/UNSAFE_OPERATION` |

أثر الدالة المركبة هو أعلى أثر يظهر على أي مسار قابل للوصول، مع اعتبار المجهول حاجزًا fail-closed لا قيمةً محايدة.

## 5. عقد الساحة

يجوز للدالة الموسومة `بلا_تخصيص` استعمال arena ثابتة منشأة قبل دخولها، بشرط أن تكون السعة، ونوع العنصر، وحدود القراءة والكتابة، وهوية المالك، وفهرس البداية والنهاية معلنة في العقد. لا يجوز للدالة:

1. توسيع الساحة أو إنشاء arena جديدة.
2. تحويل فهرس غير موثّق إلى عنوان أو مؤشر خام.
3. قبول فهرس خارج المجال أو حساب حد يفيض عدديًا.
4. تمرير ملكية الساحة إلى مسار مجهول الأثر.
5. استخدام الذاكرة بعد انتهاء نطاقها المعلن.

التمثيل المعتمد هو فهرس صحيح محدود المجال؛ أما المؤشر الخام فمرفوض حتى لو كان التنفيذ الفعلي يستخدمه داخليًا في backend.

## 6. بوابة AST

قبل أي تنفيذ، يجب أن يثبت سجل AST الآتي:

| الفحص | النتيجة المطلوبة |
|---|---|
| وجود السمة في عقدة الدالة | موجودة ومحللة، لا تعليق نصي |
| تحليل جميع المسارات | مكتمل؛ لا عقدة مجهولة |
| تحليل الاستدعاءات | كل callee له أثر مصرح أو يسبب امتناعًا |
| فحص البدائيات | كل primitive مصنف في جدول ABI |
| منع العمليات الخطرة | لا `eval`، ولا `exec`، ولا `source_ref`، ولا شبكة |
| فحص الساحة | نطاقات وفهارس ثابتة ومحدودة |
| حالة الفشل | لا artifact عند الرفض أو الامتناع |

## 7. حالات القرار

```text
PASS/ALLOC_NONE
PASS/ALLOC_ARENA_ONLY
REJECT/ALLOCATION_EFFECT
ABSTAIN/UNKNOWN_EFFECT
REJECT/UNSAFE_OPERATION
ABSTAIN/ABI_UNCLASSIFIED
```

لا يتحول `ABSTAIN` إلى `PASS` بالافتراض أو بإزالة العقدة المخالفة. يجب إصلاح النموذج أو توسيع العقد ثم إعادة التحليل من الصفر.

## 8. شروط الإثبات المحدود

لا يجوز استعمال `EXTENSION_SCOPED_PROVEN` إلا بعد تحقق جميع الشروط التالية داخل امتداد مسمى وإصدار محدد:

| الشرط | الدليل |
|---|---|
| دلالة ثابتة | جدول أثر canonical وقواعد join منشورة |
| تحليل AST | سجل كامل يضم الموجب والمخالف والمجهول |
| ABI آمن | قائمة primitives مفحوصة ومنع النداءات غير المصنفة |
| تنفيذ مزدوج | مقارنة MAL مع مرجع مستقل على نفس corpus |
| إعادة إنتاج | stdout/stderr وبصمات وسلسلة تحقق ناجحة |

حتى بعد تحققها، لا يثبت العقد غياب GC أو ثبات الزمن أو السلامة على جميع backends. أي ادعاء يتجاوز نطاق الامتداد يبقى `RESEARCH` أو `ABSTAIN`.

## 9. الوضع الحالي

```text
CLASSIFICATION=RESEARCH
RULES_EXECUTIVELY_ADOPTED=0
AST_IMPLEMENTATION=NOT_PERFORMED
DUAL_EXECUTION=NOT_PERFORMED
RAW_POINTERS=DENY
DYNAMIC_ALLOCATION=DENY_UNLESS_CONTRACTED
NETWORK=DISABLED_BY_CONTRACT
SOURCE_REF_EXECUTION=DENY
BASELINE_MODIFIED=NO
```

هذا العقد مواصفة بحثية قابلة للمراجعة، وليس إعلانًا عن توفر سمة `بلا_تخصيص` في compiler الحالي.
