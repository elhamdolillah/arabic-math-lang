# عقد MAL عند_الترجمة v0.1

**الحالة:** `RESEARCH`

**النطاق:** امتداد بحثي لتحويل AST قبل التحقق النوعي والتوليد في بيئة UORI.

**التاريخ المرجعي:** 2026-08-25

**المرجع الأبوي:** Grammar v0.1 وbaseline النواة المجمد.

**سياسة الاعتماد:** هذا العقد لا يضيف صياغة إلى Grammar النشطة، ولا يغير ABI، ولا ينشئ ميزة runtime، ولا يسمح بالترفيع التلقائي.

```text
CONTRACT_ID=MAL-COMPILE-TIME-0.1
CLASSIFICATION=RESEARCH
GRAMMAR_MODIFIED=NO
RUNTIME_FEATURE=NOT_ADMITTED
RAW_POINTERS=DENY
SOURCE_REF_EXECUTION=DENY
EVAL_EXEC=DENY
AUTO_PROMOTION=DENY
BASELINE_KERNEL=UNCHANGED
```

## 1. الغرض

يعرّف هذا العقد آلية اختيار ساكن تسمى `عند_الترجمة`. وظيفتها تحديد العقد التي تدخل في AST المصفّى قبل فحص الأنواع، وتحليل الملكية، وتحليل أثر التخصيص، والتحسين، وتوليد الهدف. لا تختار الآلية سلوكًا أثناء التشغيل، ولا تنشئ فرعًا ديناميكيًا، ولا تقرأ الساعة أو الشبكة أو البيئة غير المعلنة.

الصياغة التالية تمثيل بحثي فقط وليست جزءًا من Grammar v0.1:

```text
عند_الترجمة(المسندة) {
    جسم_الفرع
}
```

## 2. المصطلحات

| المصطلح | التعريف الحاكم |
|---|---|
| إعداد | زوج canonical من `مفتاح` و`قيمة` موجود في manifest المصرح به |
| مجموعة الإعدادات | مجموعة إعدادات البناء الكاملة بعد التحقق والتطبيع |
| المسندة | شجرة منطقية لاختيار فرع ساكن |
| AST الخام | الشجرة الناتجة قبل تقييم `عند_الترجمة` |
| AST المصفّى | الشجرة بعد حذف الفروع ذات المسندة الكاذبة وإبقاء الفروع الصحيحة |
| حالة الامتناع | نتيجة بلا قبول وبلا Artifact تنفيذي عند الغموض أو نقص الدليل |
| بصمة الإعدادات | SHA-256 للتمثيل canonical لمجموعة الإعدادات والعقد المرتبطة بها |
| هوية Artifact | سجل يربط الملف الناتج بمدخلات البناء وبصمات المصدر وAST والإعدادات |

## 3. شكل المسندة الأدنى

لا تقبل الآلية إلا المسندات الآتية بعد اعتماد parser خاص بالعقد:

```text
مسندة ::= صحيح
        | خطأ
        | اسم(مفتاح)
        | مساواة(مفتاح، قيمة)
        | كل(مسندة، ...)
        | أي(مسندة، ...)
        | ليس(مسندة)
```

ولا تقبل v0.1 المقارنات العددية، أو التعبيرات الحسابية، أو استدعاء الدوال، أو قراءة الملفات، أو قراءة متغيرات البيئة، أو `source_ref`، أو `eval`، أو `exec` داخل المسندة.

## 4. manifest المصرح به

يجب أن يأتي مصدر الإعدادات من manifest خارجي versioned وموقع أو موثق بالبصمة. ويجب أن يعرّف manifest على الأقل:

```text
contract_id
compiler_version
target
features
profile
endianness
word_size
allowed_keys
```

لا يجوز للمصدر أن يضيف مفتاحًا إلى `allowed_keys` أو أن يغيّر قيمة إعداد بعد بدء التحويل. أي إعداد خارج القائمة المعلنة يؤدي إلى `ABSTAIN / UNKNOWN_CONFIGURATION`.

## 5. قواعد التطبيع canonicalization

التطبيع هو جزء من الدلالة، وليس خطوة تنسيق اختيارية. يجب أن تنتج كل مدخلات متكافئة تمثيلًا واحدًا قبل حساب البصمة.

### 5.1 أسماء المفاتيح والقيم

تُقصر المفاتيح على مجموعة ASCII canonical محددة في manifest، مثل `target` و`feature` و`profile`. أما النصوص العربية في حقول الوصف فلا تدخل في قرار المسندة إلا إذا عرّف العقد ترميزها صراحة.

تُرفض المسافات المحيطة، والمحارف غير المرئية، ومحارف التحكم، وتطابقات Unicode غير المعيارية. لا يجوز تطبيق تحويل حالة الأحرف تلقائيًا؛ فإذا كانت المفاتيح حساسة للحالة فالتطابق حرفي، وأي اختلاف يؤدي إلى الامتناع.

### 5.2 القوائم

تُمثَّل قائمة الميزات كعناصر UTF-8 صحيحة ومصرح بها. تُزال التكرارات فقط إذا أعلن manifest أن الحقل مجموعة؛ أما الحقول ذات الدلالة الترتيبية فتحتفظ بترتيبها. لا يجوز افتراض أن قائمة مرتبة ومجموعة غير مرتبة متكافئتان.

### 5.3 الأعداد والأنواع

لا تُقبل الأعداد العشرية أو `NaN` أو `Infinity` أو التحويلات الضمنية. تُكتب الأعداد الصحيحة بصيغة عشرية canonical بلا أصفار بادئة، مع إشارة سالبة فقط عند السماح بها صراحة. ويجب أن يحدد كل مفتاح نوعه قبل تقييم المسندة.

### 5.4 المسندات

تُطبع الشجرة المنطقية إلى ترتيب prefix ثابت:

```text
مساواة(مفتاح، قيمة)
كل(مسندة_1، مسندة_2، ...)
أي(مسندة_1، مسندة_2، ...)
ليس(مسندة)
```

تُزال الأقواس غير الدلالية فقط. لا تُعاد كتابة `كل` أو `أي` بتبديل الترتيب ما لم ينص العقد على أن الأبناء مجموعة غير مرتبة. في v0.1، ترتيب الأبناء دلالي ويُحفظ كما ورد في AST canonical.

### 5.5 تمثيل البايتات

يستخدم التمثيل النهائي UTF-8 دون BOM، وفواصل أسطر LF، ومسارًا نسبيًا canonical، ولا يحتوي على وقت أو مسار مطلق أو معرف عملية أو رقم عشوائي. يضاف محرف نهاية سطر واحد فقط إلى السجل النصي النهائي.

### 5.6 ترتيب الحقول

ترتب حقول manifest المعروفة وفق ترتيب schema الثابت، لا وفق ترتيب إدخال المستخدم. وداخل الحقول المعلنة كمجموعات، يكون الترتيب UTF-8 المعجمي للتمثيل canonical؛ وداخل الحقول الترتيبية، يحفظ ترتيبها الأصلي.

## 6. التمثيل canonical المقترح

يستخدم UORI سجلًا نصيًا line-oriented واضح الحدود بدل الاعتماد على serializer غير مثبت:

```text
uori-config-v=0.1
contract_id=MAL-COMPILE-TIME-0.1
compiler_version=...
target=...
word_size=...
endianness=...
profile=...
feature[0]=...
feature[1]=...
source_path=...
source_sha256=...
ast_raw_sha256=...
ast_filtered_sha256=...
```

تُرتب الأسطر حسب schema، وتُحسم القيم قبل حساب البصمة. لا تدخل `configuration_sha256` نفسها في المادة التي تُهشَّش، حتى لا تنشأ حلقة ذاتية.

## 7. ربط Configuration Hash بالـ Artifact

لا يكفي وضع البصمة في اسم الملف؛ لأن الاسم قد يُنسخ أو يُعاد تسميته. الربط الحاكم يكون بسجل sidecar مستقل، وبفحص لاحق يثبت أن الملف يطابق السجل.

يُنشأ أولًا:

```text
C = canonical_configuration_bytes
Hc = SHA256(C)
```

ثم تُحسب بصمات المدخلات:

```text
Hs = SHA256(source_bytes)
Hr = SHA256(raw_ast_canonical_bytes)
Hf = SHA256(filtered_ast_canonical_bytes)
```

وبعد اكتمال التوليد:

```text
Ha = SHA256(artifact_bytes)
```

ويُكتب sidecar بالصيغة التالية:

```text
artifact_schema=UORI-ARTIFACT-0.1
artifact_path=build/<canonical-relative-path>
artifact_sha256=<Ha>
configuration_sha256=<Hc>
source_sha256=<Hs>
ast_raw_sha256=<Hr>
ast_filtered_sha256=<Hf>
compiler_version=<version>
target=<target>
status=PASS
```

ويُسمح بتسمية قابلة للقراءة مثل:

```text
<artifact-stem>.cfg-<Hc-prefix>.artifact
```

لكن `Hc-prefix` ليس بديلًا عن `Hc` الكامل في sidecar. يكون قبول Artifact مشروطًا بتساوي البصمات الأربع، وبصحة المسار النسبي، وبنجاح `sha256sum -c` للسجل الخارجي. إذا تطابقت البصمة الجزئية في الاسم ولم تتطابق البصمة الكاملة، فالقرار `REJECT / ARTIFACT_HASH_MISMATCH`.

## 8. خوارزمية التحقق من Artifact

```text
قراءة manifest
تطبيع manifest
إذا فشل التطبيع: امتنع
حساب Hc
تحليل المصدر إلى AST خام
حساب Hr
تقييم المسندات
إذا ظهر إعداد مجهول أو مسندة غير محسومة: امتنع
إنتاج AST مصفّى
حساب Hf
توليد Artifact مؤقت خارج مسار الاعتماد
حساب Ha
كتابة sidecar بعد اكتمال Artifact
التحقق من Ha وHc وHs وHr وHf
إذا نجحت جميعها: قبول Artifact داخل نطاق العقد
وإلا: حذف Artifact المؤقت وإرجاع الامتناع
```

لا يُنقل Artifact المؤقت إلى مسار الاعتماد قبل نجاح التحقق. ولا يُرفع sidecar أو artifact عند فشل أي خطوة؛ وذلك لمنع بقاء دليل stale من تشغيل سابق.

## 9. دلالة التقييم

| المسندة | نتيجة التقييم |
|---|---|
| `صحيح` | `TRUE` |
| `خطأ` | `FALSE` |
| اسم إعداد موجود بقيمة صحيحة | `TRUE` |
| اسم إعداد موجود بقيمة خاطئة | `FALSE` |
| مفتاح مجهول | `ABSTAIN / UNKNOWN_CONFIGURATION` |
| قيمة من نوع خاطئ | `ABSTAIN / TYPE_MISMATCH` |
| `كل()` | `TRUE`، بعد تثبيت هذه الدلالة في العقد |
| `أي()` | `FALSE`، بعد تثبيت هذه الدلالة في العقد |
| `ليس(x)` عند امتناع `x` | `ABSTAIN`، وليس `TRUE` |
| مسندة تحوي استدعاءً أو أثرًا خارجيًا | `ABSTAIN / NON_STATIC_PREDICATE` |

ولا يجوز تحويل `ABSTAIN` إلى `FALSE`؛ لأن ذلك قد يحذف فرعًا صحيحًا بسبب نقص معلومات بدل إثبات عدم انطباقه.

## 10. حالات الامتناع الإلزامية

يجب أن يكون القرار `ABSTAIN` بلا Artifact تنفيذي في الحالات التالية:

| الرمز | الحالة |
|---|---|
| `UNKNOWN_CONFIGURATION` | مفتاح أو قيمة غير موجودة في manifest المصرح به |
| `MISSING_CONFIGURATION` | غياب إعداد مطلوب لتقييم المسندة |
| `TYPE_MISMATCH` | قيمة لا تطابق النوع المعلن |
| `NON_CANONICAL_INPUT` | محارف أو ترتيب أو ترميز غير canonical |
| `DUPLICATE_CONFLICT` | تكرار المفتاح مع قيم متعارضة |
| `NON_STATIC_PREDICATE` | استدعاء أو قراءة خارجية داخل المسندة |
| `UNRESOLVED_PREDICATE` | تعذر إثبات TRUE أو FALSE حتميًا |
| `AST_HASH_MISMATCH` | اختلاف بين AST المسجل وAST المستعمل |
| `ARTIFACT_HASH_MISMATCH` | اختلاف بايتات artifact عن sidecar |
| `CONFIG_HASH_MISMATCH` | artifact مبني بإعدادات غير البصمة المطلوبة |
| `COMPILER_VERSION_MISMATCH` | اختلاف نسخة compiler عن السجل |
| `TARGET_MISMATCH` | اختلاف الهدف أو endianness أو word size |
| `CHAIN_VERIFY_FAILED` | فشل سلسلة SHA-256 |
| `TOOL_UNAVAILABLE` | غياب أداة لازمة للتحقق الحتمي |

## 11. حالات الرفض الصريح

يكون القرار `REJECT` بدل `ABSTAIN` عندما يثبت وجود مخالفة بنيوية، مثل محاولة المصدر تنفيذ `source_ref` أو `eval` أو `exec`، أو إدخال runtime dispatch، أو استخدام مؤشر خام، أو كسر ABI المعلن. الفرق أن `ABSTAIN` يعني نقص القدرة على الحسم، بينما `REJECT` يعني ثبوت مخالفة العقد.

## 12. العلاقة مع `بلا_تخصيص`

تُطبق `عند_الترجمة` قبل تحليل أثر التخصيص. الفروع المحذوفة لا تدخل في تحليل الأثر، أما AST المصفّى فيمر كاملًا عبر عقد `بلا_تخصيص`. لذلك لا يجوز لفرع غير مختار أن يخفض نتيجة الفرع المختار، ولا يجوز لفرع مختار ذي تخصيص ديناميكي أن يختبئ خلف مسندة ناجحة.

## 13. corpus الأدنى قبل أي تفعيل

يجب إنشاء corpus مستقل يحتوي على الأقل على:

| الحالة | النتيجة المتوقعة |
|---|---|
| إعداد صحيح وفرع مطابق | AST مصفّى وArtifact مقبول داخل الامتداد |
| إعداد صحيح وفرع غير مطابق | الفرع يحذف حتميًا |
| مفتاح مجهول | `ABSTAIN / UNKNOWN_CONFIGURATION` |
| قيمة مكررة متعارضة | `ABSTAIN / DUPLICATE_CONFLICT` |
| ترتيبان متكافئان حسب schema | نفس `Hc` |
| اختلاف قيمة واحدة | اختلاف `Hc` ورفض artifact القديم |
| AST خام متغير | اختلاف `Hr` وامتناع |
| AST مصفّى متغير | اختلاف `Hf` وامتناع |
| بايت واحد متغير في artifact | اختلاف `Ha` ورفض |
| فرع مختار يحوي تخصيصًا ديناميكيًا | رفض عقد `بلا_تخصيص` |
| مسندة تقرأ الساعة أو الشبكة | `ABSTAIN / NON_STATIC_PREDICATE` |

## 14. معيار الانتقال من RESEARCH

لا تنتقل الآلية إلى `EXTENSION_SCOPED_PROVEN` إلا بعد تحقق الشروط الأربعة:

1. وجود parser وAST فعليين يميزان المسندة عن runtime code.
2. تطبيع موثق ومختبر ينتج `Hc` ثابتًا عبر تشغيلات مستقلة.
3. ربط sidecar ناجح مع `Hs`, `Hr`, `Hf`, `Hc`, و`Ha`، مع سلسلة SHA-256 ناجحة.
4. corpus موجب وسالب، وتنفيذ مزدوج مستقل، وعدم وجود مؤشرات خام أو تخصيص أو source execution خارج العقد.

ولا يرفع هذا التصنيف الآلية إلى Grammar العامة أو kernel أو WASM دون إثبات مستقل لكل نطاق.

## 16. حدود صريحة

هذا العقد يثبت تصميمًا قابلًا للبحث، لا تنفيذًا في `math_complete.py`. ولا يثبت أن serializer أو evaluator أو sidecar verifier الحالي يحقق هذه القواعد. لا يجوز حذف النظير Python، أو إعلان `PROVEN`، أو تغيير baseline، أو إنتاج artifact موثوق باسم هذا العقد قبل إنشاء سجل AST فعلي وتشغيل corpus مستقل وتثبيت الأدلة.
