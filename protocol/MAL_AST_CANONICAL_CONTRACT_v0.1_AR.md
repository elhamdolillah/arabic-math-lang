# عقد AST canonical وبصماته — الإصدار 0.1

يمثل AST سجلًا فهرسيًا فقط. لكل عقدة `node_id` و`kind` وحقول أبناء من نوع NodeID أو `value_id`. لا تُدرج عناوين أو مؤشرات أو أوقات أو مسارات مطلقة في التمثيل canonical.

يُطبع AST بترتيب `node_id` تصاعديًا، وتُطبع حقول كل عقدة بترتيب المخطط الثابت، وتُحوّل القيم النصية إلى UTF-8 canonical قبل حساب SHA-256. لا يجوز استخدام ترتيب قاموس غير مقرر أو رقم عشوائي أو معرف بيئة.

تتكون بصمة الإعدادات من الإصدار، وحدود Arena، وحدود الوقود، وإصدار العقد، وكلها مرتبة حقلًا حقلًا. يُرفق `config_hash` و`ast_hash` في sidecar مع مسار منطقي نسبي فقط. إذا غاب أي حقل أو اختلفت البصمة، فالقرار `ABSTAIN / CONFIG_HASH_MISMATCH`.

لا يدل تطابق البصمة النصية على التكافؤ التنفيذي للمصدر. لذلك يظل `SOURCE_REF_EXECUTED=NO` إلى حين وجود مشغل موثوق ومخرج AST خام قابل لإعادة التشغيل.

| العنصر | السياسة |
|---|---|
| ترتيب العقد | `node_id` تصاعدي |
| ترميز النص | UTF-8 canonical |
| البصمة | SHA-256 |
| الزمن والشبكة | محظوران في المسار الحتمي |
| المؤشرات الخام | `DENY` |
| اختلاف الإعدادات | `ABSTAIN` |
| تنفيذ المصدر | `NOT_PERFORMED` |
