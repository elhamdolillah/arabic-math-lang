# عقد حماية الفرع الرئيس لمشروع MAL/UORI

**الإصدار:** 0.1

**الحالة:** POLICY / تنفيذ لاحق بعد نشر workflow

## 1. الغرض

يحدد هذا العقد الحد الأدنى الإلزامي لحماية الفرع `main` من دمج أي تغيير لا يثبت تطابق مخرجات التدقيق الحتمي عبر Ubuntu وAlpine Linux مع `musl libc`.

## 2. فحص الحالة الإلزامي

يجب أن يكون فحص GitHub Actions التالي مطلوباً قبل الدمج:

```text
Compare cross-environment SHA-256 manifests
```

يمثل هذا الاسم قيمة `jobs.mal-cross-env-compare.name` في workflow، وليس اسماً وصفياً قابلاً للتغيير في إعدادات الحماية. أي تغيير لهذا الاسم يتطلب تحديثاً متزامناً لهذا العقد وإعداد Required Status Check.

## 3. شروط النجاح

لا ينجح الفحص إلا إذا تحققت الشروط التالية جميعاً:

1. اكتملت وظائف Ubuntu 22.04 وUbuntu 24.04 بنجاح.
2. اكتملت وظيفة `alpine-3.20-musl` بنجاح داخل حاوية Alpine تستخدم `musl libc`.
3. نُزّلت جميع manifestات البيئات المطلوبة.
4. مرّ `compare_mal_cross_env_manifests.py` دون خطأ.
5. ظهر السطر الحتمي التالي حرفياً في stdout:

```text
CROSS_ENV_COMPARE=PASS
```

6. لم يحدث `ABSTAIN` أو `DENY` غير موثق، ولم تُتجاوز أخطاء التشغيل باستخدام `continue-on-error`.

## 4. سياسة الفشل المغلق

في حالة غياب الفحص، أو فشل إحدى البيئات، أو تعذر تنزيل artifact، أو عدم تطابق أي بصمة SHA-256، يجب أن تكون النتيجة **عدم السماح بالدمج**. لا يجوز تحويل الفشل إلى نجاح شكلي، ولا يجوز اعتماد manifest ناقص، ولا يجوز قبول مقارنة لا تحتوي على كل البيئات المحددة في المصفوفة.

## 5. إعداد GitHub المطلوب

من إعدادات المستودع، يجب إنشاء قاعدة حماية للفرع `main` مع تفعيل المتطلبات الآتية:

- Require a pull request before merging.
- Require status checks to pass before merging.
- إضافة الفحص `Compare cross-environment SHA-256 manifests` إلى قائمة الفحوص المطلوبة.
- تفعيل تحديث الفرع قبل الدمج عند اعتماد سياسة المستودع لذلك.
- منع تجاوز المتطلبات من قبل المسؤولين إذا كان الهدف حماية خط الأساس المجمد.
- منع force-push وحذف الفرع `main`.

تُطبق القاعدة بعد نشر workflow في المستودع البعيد وتشغيله مرة واحدة على Pull Request، لأن GitHub لا يستطيع اختيار فحص لم يُنشأ بعد.

## 6. مرجع الخط الأساس

لا تعدل حماية الفرع هذا الخط الأساس المجمد `f56b8bd`. أي تطوير جديد يجب أن يمر عبر فرع التبني، ثم Pull Request، ثم الفحص الإلزامي أعلاه.

## 7. دليل التدقيق

يجب حفظ artifacts التالية لكل تشغيل ناجح:

- manifest مستقل لكل بيئة.
- stdout مستقل لكل بيئة.
- بصمة SHA-256 لكل manifest وstdout.
- `comparison.json` و`comparison.stdout` و`comparison.sha256`.
- تقرير Pull Request عند تشغيل الفحص على Pull Request.

**قرار العقد:** غياب أي دليل أو غموض في المقارنة يؤدي إلى `ABSTAIN` تشغيلياً، ويُعامل في حماية الفرع كفشل يمنع الدمج.
