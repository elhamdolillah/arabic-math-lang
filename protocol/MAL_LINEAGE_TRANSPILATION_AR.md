# عقد التحويل من سجل سلالات اللغات إلى MAL/UORI

**الإصدار:** 0.1.0
**الحالة:** `EXTENSION_SCOPED_PROVEN`
**النطاق:** تحويل حتمي ساكن لمجموعة فرعية من المرفق إلى MAL v0.1، ثم فحصها عبر UORI.

## القرار الدستوري

1. يُقرأ المرفق كمعطى توثيقي، ولا تُنفذ أمثلته الأصلية.
2. لا تُنقل إلى MAL إلا الصيغ التي تمثلها Grammar v0.1 دون مؤشرات خام أو I/O أو مصادر خارجية.
3. الحساب الحقيقي العائم، التوليد الديناميكي، الاستدلال غير المحكوم، والـ runtime غير المحدد تبقى `RESEARCH` أو `ABSTAIN`.
4. `eval` و`exec` و`source_ref` غير الموثق والمؤشرات الخام `DENY`.
5. أي اختلاف بصمة أو غموض دلالي يمنع الدمج ويصدر `ABSTAIN`.

## ناتج التحويل

الملف `examples/lineage_mechanisms_projection.mal` يمثل إسقاطاً نحوياً محدوداً للآليات التالية:

| آلية المصدر | إسقاط MAL |
|---|---|
| ALGOL/BNF | بنية برنامج وكتل ودوال |
| Pascal/Ada | أنواع صحيحة وشروط صريحة |
| Fortran | دوال حسابية بلا I/O |
| Prolog | قرار شرطي مضبوط، لا backtracking |
| Forth | تسلسل عمليات صريح، دون stack runtime |
| Rust/Arena | لا يُنفذ هنا؛ عقد الملكية يبقى في Rust Arena |

## ما لم يُحوّل

الأنواع العامة، القوائم/المصفوفات، GADT، القيم الرمزية، persistent vectors، endianness، العمليات العائمة، التزامن، GC، dynamic dispatch، وواجهات النظام لا تمثلها MAL Grammar v0.1 كاملة؛ لذلك لم تُزعم عملية تحويلها. تصنيفها يبقى `RESEARCH` أو `ABSTAIN` حسب العقد المقابل.

## تكامل UORI

أُضيف `extensions/uori_mal_lineage.py` إلى مصدر UORI. وظيفته قراءة ملف MAL كبيانات، حساب SHA-256، إصدار قرار `ALLOW/DENY/ABSTAIN`، وإرجاع:

```text
EXECUTION=NOT_PERFORMED
SOURCE_EXECUTED=NO
NETWORK=DISABLED_BY_CONTRACT
```

لا يستدعي هذا التكامل مترجماً لتنفيذ الملف، ولا يبحث عن مصدر بديل، ولا يفتح شبكة. قرار `ALLOW` هنا يعني **قبول الفحص الساكن** فقط، وليس تصريحاً بالتنفيذ.

## حدود الإثبات

نجاح parser وUORI static inspection يثبت سلامة البنية ومسار القرار فقط. لا يثبت بعد صحة backend native أو WASM أو ملكية الذاكرة داخل MAL؛ تلك مراحل منفصلة تحتاج مواصفات واختبارات وأدلة مستقلة.
