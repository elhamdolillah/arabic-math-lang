# عقد تدقيق الذاكرة والحدود — الإصدار 0.1

تُدار الذاكرة المنطقية عبر Arena ثابتة، ولا تظهر عناوين ذاكرة أو مؤشرات خام في AST أو IR أو artifact. كل وصول يمر عبر `node_id` أو `value_id` مع فحص المجال قبل القراءة والكتابة.

تُرفض السعة الصفرية، والفهرس السالب، والفهرس الذي يساوي السعة أو يتجاوزها، وإعادة الكتابة بعد إغلاق Arena. وتُرفض محاولات الالتفاف الحسابي عند جمع الإزاحات أو أحجام السجلات.

لا يسمح المسار الحتمي بتخصيص لاحق أو تحرير يعتمد على التوقيت. عند نفاد Arena أو تجاوز الوقود أو ظهور فيض عددي تكون النتيجة `ABSTAIN` ولا يُنتج artifact صالحًا.

| الحارس | القرار |
|---|---|
| `node_id=0` | `ABSTAIN / INVALID_NODE_ID` |
| `node_id >= capacity` | `ABSTAIN / NODE_ID_OUT_OF_RANGE` |
| Arena ممتلئة | `ABSTAIN / ARENA_EXHAUSTED` |
| فيض في الحساب | `ABSTAIN / ARITHMETIC_OVERFLOW` |
| تخصيص لاحق | `ABSTAIN / LATE_ALLOCATION` |
| جميع الفحوص ناجحة | `PASS / MEMORY_BOUNDS_READY` |

تُصنَّف قواعد الذاكرة `POLICY`، أما إثباتها بالتنفيذ العربي فيبقى `RESEARCH` حتى توافر مشغل MAL موثوق.
