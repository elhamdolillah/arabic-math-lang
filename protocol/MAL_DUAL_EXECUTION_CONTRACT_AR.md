# عقد التحقق المزدوج بين MAL العربية وPython

**الإصدار:** `MAL_DUAL_EXECUTION_v0.1`

## الغرض

كل مهمة مرشحة للهجرة تُحفظ لها نسخة مصدر عربية بامتداد `.ar` ومرجع Python بامتداد `.py`. عند وجود منفذ MAL تنفذ النسختان على نفس corpus ونفس المدخلات، ثم تطبعان خرجاً canonical قابلاً للمقارنة. لا تُقبل النتيجة لمجرد نجاح أحد المسارين.

## حالات القرار

| الحالة | المعنى |
|---|---|
| `MATCH` | خرج `.ar` و`.py` متطابقان byte-for-byte بعد canonicalization، مع أدلة متطابقة |
| `MISMATCH` | كلا المسارين اشتغلا لكن النتيجة مختلفة؛ القرار `ABSTAIN` ويُفتح إصلاح مراجَع |
| `MAL_AR_ERROR` | فشل منفذ `.ar`؛ لا يُستبدل بمرجع Python |
| `PY_ERROR` | فشل المرجع Python؛ لا تُستعمل نتيجة عربية منفردة |
| `GAP` | لا يوجد منفذ `.ar` أو مكتبة لازمة؛ يسجل النقص للعودة إليه لاحقاً |

## قواعد الأمان

لا يسمح harness بتنفيذ `eval` أو `exec` أو `source_ref` أو network أو subprocess داخل مصدر MAL نفسه. يسمح فقط باستدعاء منفذ MAL موثق ومحدد مسبقاً عبر argv منفصل، وبـtimeout ثابت، وبيئة locale وhash ثابتة. لا يغير harness المصدر أو baseline ولا ينشئ merge أو يرفع التصنيف.

## التصحيح والتصنيف

عند `MISMATCH` لا يصحح النظام النسخة العربية تلقائياً. يسجل المدخل، خرج المسارين، SHA-256، وأول فرق canonical، ثم يصنف الحالة `ABSTAIN` حتى تُراجع الدلالة. عند `GAP` يسجل capability ناقصة مثل `MAL_RUNTIME` أو `MAL_COLLECTIONS` أو `MAL_FILE_IO`، ولا يحول النقص إلى فشل في اللغة.

## معيار PROVEN

لا تنتقل المهمة إلى `PROVEN` إلا بعد تشغيل `.ar` و`.py` على corpus موجب وسالب، وثلاث تشغيلات متطابقة على Ubuntu وAlpine، وسلسلة SHA-256 مكتملة، ومراجعة بشرية. وجود parser أو transpiler فقط لا يساوي تنفيذ MAL.
