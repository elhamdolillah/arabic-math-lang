# النموذج الأولي لنواة UORI v0.1

## الحكم

هذا النموذج **مرجع تنفيذي حتمي قابل للاختبار**، وليس بعد نواة bare-metal قابلة للإقلاع من BIOS أو UEFI. يثبت الحلقة الآمنة التالية:

```text
إدخال عربي محدد
  ← تحليل نية محدود
  ← البحث في سجل خوارزميات مضمّن
  ← فحص الدليل والموارد
  ← تنفيذ حتمي معروف
  ← نتيجة تحمل بصمة الدليل
```

لا يقرأ النموذج أجهزة حقيقية، ولا يحمّل برامج تشغيل من الشبكة، ولا ينفذ كوداً مولداً من LLM، ولا يستعمل `eval` أو `exec` أو `subprocess` أو مؤشرات أجهزة خام.

## ما نُفذ

| الطبقة | الحالة | الدليل |
|---|---:|---|
| ملف عتاد مرجعي | منفذ | `python/uori_kernel.py` |
| إقلاع منطقي | منفذ | `UoriKernel.boot()` |
| تحليل نيتين عربيتين محدودتين | منفذ | `parse_intent()` |
| سجل خوارزميات | منفذ | `AlgorithmRegistry` |
| أولوية الحتمي | منفذ | رفض التسجيل غير الحتمي |
| دليل الإنهاء وحد الموارد | منفذ | `Evidence` و`ExecutionPlan` |
| حارس الوقود للقاسم المشترك | منفذ | `_gcd()` |
| الامتناع عند طلب غير معروف | منفذ | `KernelStatus.ABSTAIN` |
| عقد Rust ABI | هيكل أولي | `rust/src/lib.rs` |
| إقلاع bare-metal فعلي | غير منفذ | يحتاج bootloader وtarget وlinker واختباراً مستقلاً |

## أمثلة

```text
احسب الجذر التربيعي لـ 144  →  12
احسب قاسم 84 30              →  6
طلب غير معروف                 →  ABSTAIN
```

## عقد ABI الأولي

يعرّف Rust الأنواع `UoriCallFrame` و`UoriReturn` ونقطة `uori_syscall`. في هذه النسخة تعيد النقطة `ABSTAIN` بعد التحقق من أن المؤشر غير فارغ، لأنها لا تملك بعد خريطة ذاكرة أو جدول قدرات أو منصة عتادية موثقة. هذا الامتناع مقصود وليس فشلاً مخفياً.

## طريقة الاختبار

```bash
cd prototypes/uori_kernel_v0_1
python3 -m unittest discover -s tests -p 'test_*.py' -v
python3 python/uori_kernel.py
```

## ما يلزم قبل رفع الحالة

يلزم تحديد calling convention نهائي، وخريطة ذاكرة، ومدخل boot، وinterrupt/exception ABI، وجدول قدرات فعلي، وlinker script، ثم تثبيت Rust/Cargo وهدف البناء. بعد ذلك فقط يمكن إضافة مسار `no_std` قابل للتجميع، ثم تشغيل QEMU، ثم اختبار bare-metal حقيقي. لا يجوز اعتبار نموذج Linux أو النموذج المرجعي دليلاً على الإقلاع العتادي.
